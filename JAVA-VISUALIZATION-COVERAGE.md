# Java visualization coverage — Milestone 11.5

Status: **completed lead audit and visual acceptance, 2026-09-30**. Compared baseline `dfa3091` with the Milestone 11.5 implementation. Final gates: 591 unit/integration tests across 62 files, 85 browser tests, build/typecheck and configured lint passed. Fresh-session JSON, screenshots and replay evidence are linked below.

## How to read the classifications

- **Full:** the stated, bounded concept has an observation and runtime presentation path without a known missing part within the scope stated in that row. This classification describes observation coverage; measured workflows below validate specific cases.
- **Partial:** some facts can reach the visualization, with the omissions or failure risks stated explicitly.
- **Unsupported:** the concept's defining state/events have no supported visualization path. Surrounding project calls, scalar locals, source lines, or console output may still appear.

The execution column describes the available launch architecture, **not a claim that a fresh project containing that construct passed**. Standard Java bytecode may execute through the configured JDK while its state is unobservable or only partially captured. Run normally instruments the compiled project; **Run without visualization** is a separate console execution choice. Preparation failure can fall back before a JVM starts; a launched JVM is never rerun automatically to recover a trace. Debug requires capture. See [ExecutionManager](server/execution-manager.mjs), `#launch`/`#plain` (lines 127–179), and [launch arguments](server/launch.mjs), `javaLaunchArgs`.

This matrix concerns real JVM capture into the normal runtime world. Richer hand-authored fixture events do not establish arbitrary Java support. In particular, fixture scopes, named loop iterations, exact array operand origins, Scanner destination bindings, and caller return destinations are not generally emitted by the JVM normalizer.

Unsupported values are generally normalized to unavailable (`uninitialized`, rendered `—`) with capability reasons. Unknown owners, incompatible scalar types, bad ordering, unobserved stale array contents or multiple threads can instead stop normalization at the first invalid event. There is no guarantee that every unsupported construct degrades gracefully; measured corpus tests must record whether the outcome is a partial world, aborted prefix, preparation fallback, or console-only run.

## Capability labels are not universal Java coverage

`ExecutionSession.support === 'FULL'` in `supportFromObserved` checks a successful recorder terminal, resolved transformed classes, core enter/line events and debug-local availability. It does **not** check all 33 concepts above, all field mutations, static fields, reference returns, collections or library internals. The backend capability report remains partial; provider feature labels can be broader than the normalizer's accepted facts. N deliberately excludes loops/scopes/console from one aggregate reduction. None of these labels certifies “all Java works.” An absent event means “not observed,” which is distinct from a language-wide implementation judgment.

[IdeWorkspace.tsx](src/ide/IdeWorkspace.tsx) now provides a **Capture limits** disclosure whenever the recording belongs to the current execution, including successful recordings. It states project-only recording, absent library internals/static fields/object arrays, unavailable values and last-observed-value limitations, and displays up to three capability diagnostics. This explanatory UI does not alter the `FULL` enum or the recorder's numeric bounds.

## Runtime presentation and measured scale

The current working diff projects every retained invocation in `buildSceneModel`, including completed/unwound frames while other frames are still active. `EXIT_METHOD` already retains frame records in S. W now emits explicit invocation status and uses subdued historical faces/edges; heap data remains normal object data. The measured workflows retain the world through completion and failure. Values remain last observed; mutations outside project probes can leave them stale.

JVM layout uses capture provenance (`trace.capture.origin`) and invocation order/depth, not example name. Calls occupy four sibling columns: X advances by 6.4 units, Y by depth at 4.2 units, and later sibling rows extend in Z at 2.6 units. Heap allocations reserve append-only shelves using object/array width and depth, with 1.2-unit spacing and shelf rollover at X 25.55. Object height is reserved by initial field count. Prefix growth therefore does not depend on current field values or a fixture algorithm. Live frame height remains fixed while slot rows can grow; a very wide array can exceed a shelf width.

`detailedScene` uses base detail budgets of **24 recent frames, 32 recent objects and 64 quiet eligible references**. Live frames, selection owners/context and prioritized reference targets are protected and can exceed these counts. The remaining frames/objects render through `ArchiveSolids` as selectable instanced cuboids at the original anchors; clicking promotes an entity to detail. The budgets reduce face-text and connection work without deleting recorded runtime state or identities. This is not a hard total-geometry cap, collection adapter, library-call collapse, or per-array-cell virtualization. Full scene projection, archive enumeration and collision volumes still depend on recorded world size. `seek.ts` separately bounds retained replay snapshots to 64 with a rolling checkpoint; measured graph load/scrubs are reported below without a universal latency guarantee.

Entity Focus now isolates the selected frame/object, a selected slot's owner, or a selected reference's endpoint entities through `isolatedScene`. Existing XYZ anchors and runtime records are unchanged; return flow/history and unrelated headings are suppressed. Scrubbing before the entity exists falls back to the ordinary world. Return to world/Home/Follow/representation changes clear isolation; user navigation can explore the isolated geometry. Collision anchors use the visible scene, while world framing retains the full scene. This entity isolation is distinct from the IDE's workspace-expansion Focus.

[cameraConstraints.ts](src/navigation/cameraConstraints.ts), `collisionSafeRoute`, uses six exterior detour candidates above 64 collision boxes rather than constructing the corner visibility graph. That large-world candidate search scans boxes in O(n); this is not an O(n) guarantee for all camera/replay work, and its fallback can constrain movement if no candidate is clear. Camera far plane and fog distances now scale with world bounds. [RuntimeLabel.tsx](src/scene/primitives/RuntimeLabel.tsx) attaches text to solid faces, fits text width and enables depth testing instead of billboarding through geometry; shared runtime font remains Inter. `ObjectSolid` enables fitted/selectable fields and limits entry animation to current allocation. Graph budget/inspection and the bounded Focus probe passed. No sustained 60 fps or arbitrary-world responsiveness result is established.

## Language-cache resource bound

Root observed **ENOSPC at 48/85 browser tests** after accumulated QA project/revision caches reached approximately **13 GB** (about 11 GB JDT indexes plus 1.6 GB generated configs). Root removed inactive generated caches while preserving the running JDT data/config; user projects and source were untouched.
