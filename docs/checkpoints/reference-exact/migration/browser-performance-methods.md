## Ordinary Java source and a fresh actual JVM

Dense_Sample means the actual Phase 5.5 Topology program in `.ggjavaez/qa/v12-p5_5/payloads/02-arrays-cycles-collections.json`, not the newer small reference inventory fixture. The harness reads only its source manifest for import. It requires exactly `Topology.java`, 1,287 UTF-8 bytes, and verifies the content against the manifest SHA-256 and the preserved known digest `97e6a390f5349cb8a474d5ff2f5de3104bad8c3f86f46fea43ad4b9e841b10da`.

It imports ordinary sources by their manifest file IDs through `POST /api/projects/import`, sets only the public project-selection localStorage key in `addInitScript`, visits `/?qa=1&perf=1`, and clicks the actual Run button. It awaits that project's execution POST and its actual new session. It requires COMPLETED, successful build, exit code zero, FULL recording and exact stdout `TOPOLOGY 73 100 1000 3 true\n`. Full fresh raw events and source manifests are saved in the ignored fresh-session snapshot; fresh source hashes are checked against the imported manifest. The old payload session ID is recorded only as provenance and must differ from the new ID. An obsolete backend ID after a bridge restart is never reused.

No old events enter the application or recording pipeline. No requests are fulfilled, replayed, redirected or manufactured. JDT remains actual. An unrelated active bridge session causes a reported failure; cleanup stops only a session belonging to the harness's imported project. Completed fresh execution remains available for root inspection.

## Native interaction timing

At least 100 seek positions cover the entire normalized recording, including zero and End. Positions are evenly spaced and permuted by the fixed coprime stride 37. Each command fills the actual public HTML range input, exactly as the Phase 5.5 baseline does, verifies its actual ARIA cursor and timeline cursor, and waits two real browser rAF callbacks. This UI control invokes the same production seek action as physical pointer/keyboard input; the harness invokes no hidden runtime/store method. The wall time includes the public range action, UI commit assertions and two-rAF first-composition boundary. Prior readiness, report writing and subsequent choreography settling are outside the measured command. Pointer/keyboard drag behavior remains covered separately by native browser checks. Fixed p50/p95 thresholds are 55/112 ms.

The source only records about 33 object identities; the harness therefore derives 50 distinct, captured reference-cell IDs from the actual 100-cell inbound array, all owned by that same indexed array. It does not turn unobserved sparse indexes into targets. Native accessible entity traversal, optional native zoom/exploration, and the actual Cluster member Inspector establish owner selection. If geometry is hidden, the harness must reach it through the current UI; failure is recorded rather than selecting through a store. Each cell is selected by its real Inspector `Reveal index N` button. Virtual rows are reached by native wheel scrolling with read-only scroll observations.

Each of the 50 actual Focus commands targets a different captured slot. Focus mode and the two-rAF boundary are observed; actual target/selection identity and the presented cell mapping are checked. Settling and readiness happen outside first-frame timing. Each Focus is followed by one actual Home command, also measured to mode commit plus two rAF callbacks. Fixed p95 limits are 125 ms Focus and 152 ms Home. These are the baseline browser composition proxies, not hardware scanout timing or full camera-travel duration. UI unreachability, a missing mapping, timeout or fewer than the required samples is a failure, not a bypass.

## Five fresh cold loads

Five newly created browser contexts open the same actual retained COMPLETED backend session. Each starts without previous frontend storage/application state except the project-selection key. The cold clock starts immediately before navigation and ends after actual recording ingestion, mounted QA readiness, native slider End, final world-at-head confirmation and world readiness. The required normalized count is computed independently from the fresh session's actual raw facts and source/terminal metadata; frontend readiness must reach that count, rather than accepting its first small catch-up prefix. Browser errors and resources are saved for each context. Failed loads remain present; they are never replaced with successful samples to produce a better median.

The fixed median budget is 5.3 seconds. The prior 4.816-second observation was one load and excluded JDT; this harness leaves the actual JDT lifecycle active and records that methodological difference. Fresh browser contexts do not promise a cold operating-system disk cache, bridge cache or Java-language-server process. They do satisfy the required absence of retained frontend application state. The context's actual build/request responses are not fabricated.

## Continuous frame windows

All five target viewports are measured: 1728×1117, 1440×900, 1280×800, 760×900 and 1440×650, with device scale factor one and actual INTERACTIVE quality. Inspector closure, Home, End and readiness occur outside the gesture. A point inside the actual Shell Safe Frame must hit the actual World. The harness holds the native primary pointer down and sends sequential native pointer moves for at least 30 seconds per viewport. Bounded coordinates vary with elapsed wall time, independently of protocol/event counts. It does not serialize an extra rAF RPC after each pointer move, which would throttle input delivery to approximately every other display frame. It issues no readiness calls, clock stepping, state setters, render requests, artificial invalidate calls or sleeps inside the orbit window.

Probe snapshots are taken only at the start and end of each continuous window. The report retains every submitted frame between these explicit boundaries, its actual IDs and display-frame timestamps, CPU duration, calls, triangles, resources, quality, continuous flag and GPU outcome. It verifies retained submission count, contiguous display-frame IDs and the actual first-to-last frame span. A 500-ms input margin lets that span reach the required duration; an insufficient measured span still fails. Samples are not filtered by favorable CPU, calls, interval, GPU availability or the continuous flag. Noncontinuous metadata and frame gaps are reported explicitly.

Only the first interval is excluded from interval percentiles, because its preceding demand-render frame lies outside the native gesture window. Its CPU, GPU and draw calls remain included. Every other frame interval is retained. This prevents a preceding demand-idle gap from being called continuous FPS while preserving slow intervals within the active window. Frame-rate claims derive from the render owner's actual display frames, never an independently sampled rAF list. This still measures browser render submission cadence, not physical monitor presentation.

Fixed limits for every viewport: median interval 16.7 ms, p95 interval 33.3 ms, every submitted frame at most 250 calls, whole-owner CPU submission p95 6.0 ms. GPU values are asynchronous actual query results; resolved, pending and unavailable samples plus omission reasons are reported separately. Unavailable GPU results never become zero-duration measurements. Capability, context-loss, lifecycle, pending-query and renderer resource evidence is retained. The probe measures the integrated complete PostPipeline owner, including its registered auxiliary reflection/contact passes; root must preserve that measurement boundary.

The runtime recording, cursor, live head and canonical anchors must remain identical while the actual camera pose changes. The report preserves resource count ranges; geometries/textures/program counts do not imply GPU memory bytes.

## Continuous 60-second drift and heap window

A separate 1440×900 continuous native orbit lasts at least 60 seconds. Explicit CDP `HeapProfiler.collectGarbage` runs before the start and directly after pointer release, outside CPU/GPU/frame timing. `Performance.getMetrics` records actual `JSHeapUsedSize` and available supporting counters. No screenshot, readiness traversal or another workload intervenes before the ending heap sample.

The first and last 10-second interval sets use actual frame timestamps and require each interval's two endpoints to fall inside the relevant window. Their IDs and distributions are saved. The absolute median change must be at most 10%; post-GC whole-frontend heap growth must be at most 5%. Missing CDP metrics, incomplete frames, a crash or a short span produces explicit NOT_MEASURED failure. A negative heap change is reported as measured rather than clamped to zero.

CDP whole-frontend heap is not isolated rich semantic retention, presentation retention or GPU memory. The 390-MiB semantic budget, 25% same-session presentation ratio and 20k/1k isolated update ratio remain external NOT_MEASURED failures/incomplete evidence. Root must use the independent semantic/modern CPU probes for those measurements. The browser does not infer these values from its heap snapshots.
