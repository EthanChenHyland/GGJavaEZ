# Flow accounting over presented semantic ports

The production planner now partitions the complete supported ExecutionGraph
edge prefix after it chooses entity detail and array windows. Current-reference
and historical-binding accounting remain separate. No normalizer, reducer,
RuntimeState, graph schema, Semantic_Golden or bytecode fact is changed.

Each supported prefix edge is counted exactly once as an individual Flow,
a directed bundle constituent, unavailable spatial evidence, or an exclusion
from the active scope/context budget. Unsupported graph kinds remain available
through complete recorded provenance; the displayed Flow count is explicitly
the supported-edge count, not all graph records. At Trace All, scope exclusions
are zero and individual plus bundled counts equal drawable candidates. Missing
sources and prefix-unproved destinations remain unavailable.

Actual ports belong to visible face rows, distinct Map key/value chips,
captured cells in the current recording/window, present bodies, recorded I/O
endpoints and the returned frame subdivision. Quiet/hidden/retired rows, absent
captured cells, ellipses and collapsed clusters supply no provenance slot port.
A captured Map value chip remains physical geometry when its current value is
null; no reference value or Java operation is inferred from that geometry.

Residual bundles group exact directed semantic endpoint kinds/identities and
edge roles, using opaque tuple keys scoped to the recording. Raw graph value
versions no longer create separate groups, and the first candidate no longer
stands in for later mappings. Every presented Flow bundle exposes its exact
graph-edge constituents in a virtual Inspector list. Native constituent
selection preserves camera, Focus, Cursor and canonical anchors.

Individual admission first retains actual drawable mandatory selected/current
evidence. Optional candidates use Selection/Focus/current/relevant priority,
then newest normalized evidence and canonical edge-ID ties. Overflow is based
on drawable mandatory candidates, not subsequently rejected port mappings;
mandatory overflow admits no optional excess.

The focused gate passes 19 tests in seven files in 3.15 seconds. Two generated
properties each run 100 cases, including a complete accepted-graph edge oracle
across FAR/MEDIUM/CLOSE and rewind. New synthetic geometry fixtures initially
used the wrong array field, omitted the required active frame and allocated a
Map with compact unknown-source geometry. They now use the accepted array
contract, a real normalized frame and explicit PROJECT metadata. Runtime
validation and geometry admission were not relaxed.

Actual BindingApp JVM captures contain 289 supported graph edges at the final
checked poses: 158 drawable and 131 unavailable; 20 individuals and 138
constituents in 13 bundles. Desktop and narrow native bundle/constituent
interaction, prefix replay and Trace scopes pass, alongside real GPU quality
gating, in the three-case 24.4-second run. The first complete-prefix oracle
attempt passed five surrounding cases but failed both history cases at cursor
zero by dereferencing a graph that does not exist yet. The oracle now expects
the actual empty prefix, with no manufacturing of a graph or facts.

The historical reference geometry remains capped at .25 opacity. Flow grouping
does not establish reference-image convergence; crossings and glow still need
polish. The complete candidate prefix is cached for an unchanged SceneModel,
but rebuilding it and evaluating all candidates at a new prefix is linear in
supported edges. This is a correctness checkpoint, not approval of the design's
million-edge indexed aggregation or the sustained performance budgets. A
modern pipeline performance harness and subsequent indexing work are required.
