# First-event collection reservations and entry geometry

`firstObjectPresentation` reads only the accepted allocation event. Ordinary
object and array formulas remain unchanged. A finite table of 28 canonical
standard collection class names selects a geometry reservation of
5.2 × 9.93 × 2.3 units. It does not establish collection kind, size, entries,
defaults or operations. Foreign same-name classes, interfaces and unknown
subclasses keep ordinary reservations. No later summary chooses first geometry.

Placement follows the existing first-event ownership/source policy. Known
collection user data with an actual allocation source joins the project heap;
recorded PROJECT metadata also does so. Source-unknown library data keeps its
compact library block forever, even if a later source/ownership/summary arrives.
Recorded ownership remains authoritative and independent of placement region;
a project-located JDK collection still has JDK metadata and grouping. The
referencing-owner branch of the complete placement policy remains outstanding.

The source-bearing actual dense-JVM ArrayList previously occupied a
4.2 × 2.4 × 1.6 library block. Its captured entries could not fit. It now reserves
the full collection geometry from its first captured runtime type/source, before
any summary exists. SceneModel still projects an ordinary observed object at
the allocation prefix. Only a captured library summary creates SceneCollection
values, size and entries. Canonical body anchors never move or resize.

`collectionEntryFace` defines the shared entry grid. MEDIUM admits the first
eight captured entries in column one; CLOSE admits up to 24 captured entries
across two columns of 12. Shared face visibility, chip solids, text, collection
summary ports and reference topology use this geometry. Maps give captured key
and value slots separate chips/ports. Reference ports lie at actual chip fronts,
with no borrowing of a value port for a key. Entries outside the reservation
retain captured Inspector data and have no spatial port. Logical `+M more`
equals recorded collection size minus entries shown, including unrecorded
positions; it does not imply those positions were captured.

The current runtime capture budget is 32 values, so normalized Map snapshots
contain at most 16 pairs. Tests retain that contract and never fabricate 24
captured Map pairs to fill the reservation. Snapshot changes are observations;
no add/remove/put/poll operation is inferred.

Generic fields captured without a collection summary retain ordinary field
ports. Explicit collection-summary observations do not populate conflicting
generic field ports for their semantic entries. Entry ports come from the
captured summary and shared grid. All lookup and selection uses recorded IDs.

The common instanced picking handler now stops pointer-down propagation at the
closest pickable hit. Previously a chip press in a face batch could be
overwritten by the background body plate in the same batch, causing a click to
select the body. Array mapping/press validation remains intact. Actual native
collection chip selection exercises this fix.

A short-viewport native double-click exposed a second batch boundary: pointer
down reached the proxy's face batch while double-click dispatch reached its
body batch. The press record now belongs to the whole solid surface, with
semantic pick identity and recording/window validation shared by both batches.
A new click test observes the actual selection publication instead of accepting
an unchanged previously selected cluster as proof of a new hit. Temporary
pointer diagnostics were removed after establishing the cause.

Collection value/size/count glyphs and identity use shared physical sizing.
The collection identity uses .34 units rather than the ordinary .28-unit
identity token, so the tall reserved face retains a readable identity at the
same physical arrival pose. Renderer and camera admission use the same shared
heading definition; this is an explicit collection typography adjustment.
Readonly QA observes actual Troika text/matrices/opacity and both face-axis
projections; it never sets pose, runtime state or selection. Desktop/narrow
dense-JVM checks cover known first geometry, actual Focus, chip picking,
prefix-before-summary/replay, 24 glyph slots, exact size/count captions and the
250 draw-call ceiling. They do not prove pixel visibility through foreground
solids or sustained performance.

The narrow test closes the existing Inspector through its native control before
explicit Focus of the tall body. Closing alone preserves the camera. An
open-sheet Focus pose remains physically obstructed in this dense arrangement.
An attempted two-angle Focus ranking did not resolve it and was removed; no
camera solver change is included. Foreground stack occlusion, connector overlap
across labels, complete Map/browser coverage, unknown collection classes, full
hierarchy, reference approval and sustained performance remain open.

## Structural proxy reservations and ownership arrival

The picking correction exposed structural proxies that occupied the first
member's runtime body. Once that member became individually presented, the
proxy for its remaining members was physically hidden inside it. Proxy cuboids
now have separate deterministic reservations outside the immutable runtime
bands. Stack/class proxies reserve space to the left; heap/library proxies
reserve space above the band's first top. Colliding proxy reservations advance
outward in X or Z. Keys are introduced in normalized event order, including
actual ownership-observation ordinals, so later knowledge and residual cuts
cannot displace an earlier proxy. Runtime bodies and ports are unchanged.

Ownership travel replaces the ownership proxy at CLOSE. A remaining actual
member can be far from the first member that established the stable proxy.
Arrival frames the actual member, measures physical CLOSE and readable glyphs,
and proves native face picking. It no longer requires the absent outgoing
proxy's position to fit that arrival view. Generic groups still frame the proxy
centre and an actual member. The bounded solver first tries its existing
centre-biased rectangle, then the complete actual Safe Frame when no centred
candidate is feasible. Collision admission and semantic zoom are unchanged.

The repeated cancellation interaction uses native Home when no Focus exists;
zooming out from a distant ownership member need not leave its stable proxy
on-screen. This setup still checks unchanged Cursor, runtime anchors, Focus and
overlays before the native double-click and manual cancellation.

The ownership arrival assertion moves from the outgoing CLOSE proxy to the
actual complete member: the same Safe Frame bounds and tolerance apply. Its
body bounds, native central-face pick and minimum 12-pixel heading checks remain
required; a new assertion proves the outgoing ownership proxy is absent. This
corrects the former proxy geometry assumption without broadening the accepted
runtime identity, arrival detail, camera stability or glyph requirements.
