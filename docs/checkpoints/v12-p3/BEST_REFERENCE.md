# Spatial 2.0 visual north star

[Root reference: best.png](../../../best.png) was inspected directly at its original 1672 × 941 size before Phase 3 fixture work. It remains in the repository root. The image is a direction for the future product, not a literal screenshot specification or evidence of Java execution.

## What to carry forward

- **Runtime-first composition:** the navigable world dominates. Source is an integrated, synchronized control surface inside that experience.
- **Genuine XYZ depth:** stack frames and heap objects are dimensional rectangular solids with visible top and side faces, perspective, and meaningful depth.
- **Readable information faces:** identities, parameters, locals, and fields remain readable on their owning frame/object faces. Readability takes priority over glow.
- **Clean semantic connections:** reference endpoints visibly attach to the actual originating slot and target object. Caller/callee and value flows must be equally explainable.
- **Historical depth:** current execution is strong; completed execution remains present and quieter. Retained history conveys call structure and time without suggesting a frame is still executing.
- **Coherent Stack and Heap regions:** stable runtime identity gives the user a recognizable place to revisit while scrubbing and exploring.
- **Integrated bottom timeline:** time navigation belongs to the world, alongside minimal contextual Focus, Trace, and Home controls.
- **Restrained cinematic darkness:** controlled contrast, materials, lighting, and depth provide atmosphere while inactive entities and ordinary controls stay calm.

These qualities extend the [spatial world contract](../../visual-java-spec/SPATIAL_WORLD.md), [design system](../../visual-java-spec/DESIGN_SYSTEM.md), [navigation contract](../../visual-java-spec/CAMERA_AND_NAVIGATION.md), and [true-3D reference guidance](../../visual-java-spec/references/README.md).

## What must not be copied literally

Do not reproduce decorative background cubes without runtime meaning, fake values, invented references, a fixed Person-specific layout, permanent neon/glow, or output floating everywhere. The displayed constructor, current method, object IDs, field values, and links are concept art; production must derive those facts from recorded execution. A translucent face is not permission to make information unreadable.

**All production geometry must correspond to real execution state/history or clearly identified structural UI.** A null reference has no heap object. Historical frames must be distinguishable from active frames. Canonical stdout/stderr remains in Console; any future spatial output node needs an actual observed operation and emitted text.

## Phase 3 foundation, not a visual rewrite

Phase 3 supplies invocation identity, actual call sites, receiver/argument bindings, observed values, bytecode producer evidence, destinations, I/O, and exception paths through the ExecutionGraph. Future Spatial arrows must cite the recorded edge/event that proves them. Unknown provenance stays unknown; names, labels, nearby source lines, and equality of values cannot establish an edge.

This phase does not reposition source, redesign the shell/timeline, replace materials, add clustering/semantic zoom, or stage a new fixed hero scene. Those changes belong to a dedicated Spatial 2.0 milestone after semantic acceptance. User camera input, persistent XYZ anchors, reduced motion, and retained completed history remain binding throughout that work.
