## Chosen architecture and contracts

Alternatives considered: a reskinned split-pane IDE would leave the runtime secondary; floating every tool would impair normal editing. Chosen: one runtime workspace with a compact activity rail, an adjustable source wing, contextual Inspector, and integrated bottom timeline/tools. The existing Monaco models, execution session, command registry, Console, debugger and source-binding pipeline remain authoritative.

- No RuntimeState, ExecutionGraph, raw/normalized trace or recorder semantics were changed. No duplicate Java process or execution model.
- Additive SceneModel contracts may carry observed class storage and existing ownership metadata. Class geometry is explicitly class storage, never a fabricated object instance. Selection gains `class` only for actual RuntimeClass IDs.
- Generic layout becomes an append-only caller-derived invocation landscape and deterministic type shelves. Frame positions derive from caller and sibling order, recursive descent adds Z-depth; completed invocations stay at their original XYZ. New type shelves and allocations never move earlier anchors. Field/local overflow stays explicit. Arrays use bounded rows of physical cells; sparse observed indices retain actual index identities.
- Curated/Theater entry remains exclusively at the app composition seam. Generic modules contain no algorithm/source-name/fixture branches. Home/heading/floor coordinates derive from represented geometry. Array presence does not trigger a camera mode or global reframe.
- Semantic zoom changes representation only: macro type/call summaries, meso bounded entities, micro readable faces. Selection/current context takes precedence; quiet volumes use instancing and budgeted picking. Cluster labels disclose actual membership counts. Anchors and semantic records remain intact.
- Detailed faces and connectors have strict presentation budgets. Scene projection reuses immutable entity records; append-only layout consumes only new events. No per-event full-trace scan.
- Focus preserves one-hop semantic context, suppresses unrelated clutter and approaches the front face without moving the entity. User input always cancels automation. Selection never starts Focus. Home fits the actual represented world. Classes and sparse cells participate in navigation.
- Provenance animations only use existing SemanticTransition / graph evidence. Direct scrub snaps without replaying intermediate motion. I/O uses bounded endpoints based on recorded I/O facts; Console retains canonical complete process output.
- Semantic colors remain central: execution cyan, stack blue, heap purple, mutation/return warm, exception red, completed control neutral grey. Readable opaque faces, dimensional bodies and restrained edges replace permanent glow. Reduced motion and visible keyboard focus remain binding.

## Integration refinements from iteration one

- The type catalog initially formed an overly wide strip. Actual type shelves now occupy three X columns with distinct Y tiers; each type keeps its own append-only Z lane. Class storage sits above its corresponding tier, separated from the next tier. This arrangement depends on observed type identity, never an algorithm name. Every old anchor remains fixed as new records arrive.
- An observed project ancestor across opaque library code is not a proven direct caller. `SceneFrameNode.callerEvidence` suppresses the physical CALL connector unless the accepted graph binds that invocation to its recorded call/caller. The observer ancestor remains available as recorded context.
- Flow history queries resolve a bounded graph adjacency/suffix window without replaying every adjacent semantic state on world load. Exact event-ID/ordinal verification is used before accessing a normalized event; arbitrary imported IDs use a bounded tail fallback. The complete graph/history remains authoritative.
- The runtime entity dropdown has a 256-option DOM budget, with search across actual recorded identities and explicit retention of selection outside the recent window. It does not duplicate semantic storage.
- Scene I/O uses actual GraphIO input consumption and emitted output, excluding submitted input bytes and file channels. At most three bounded endpoints retain fixed anchors from their first actual fact. The full Console remains canonical.
- Inspector is a compact right column. The former horizontal bottom shelf and duplicate generic completion/return readouts were removed. Timeline remains integrated along the bottom edge.
- Projected detail scale comes from the full runtime catalog, avoiding a macro/meso feedback loop caused by measuring different LOD populations.

## Further convergence changes

This remains observed caller geography, not a scene chosen by method name.
- Project and external type shelves maintain separate ordinal ranges. A large observed JDK catalog cannot push later project classes many Y tiers away. Metadata is accepted recorder ownership; missing metadata retains the generic observed path.

- Macro overview labels are bounded camera-facing annotations of represented cuboids/groups with actual membership counts. Short type names are presentation only; Inspector retains full identities/types. Projection sizing and overlap culling keep captions legible without a giant DOM overlay or hidden semantic records.
- Home includes promoted reference context as well as cluster representatives and observed I/O. Free exploration refreshes spatial relevance on coarse target tiles, avoiding full React replanning on every orbit frame.
- Focus reveals side/top depth with an 18-degree side view while fitting the information face. At most two nearby observed neighbors can add up to 15% camera distance. Floor geometry is omitted during close inspection to keep the selected face primary.
- The runtime source wing remembers manual width separately from expanded editing. Run/rerun does not overwrite a chosen runtime width. Completed unpinned Console collapses; actual input waits, failures and debugger inspection remain reachable.

## Scope and follow-up

Only OpenJDK 26.0.2.1 on macOS arm64 was exercised as a runtime. Release-17 Maven/Gradle compilation is not JDK-17 execution testing. Existing limits remain: project observation rather than complete JVM instrumentation, unsupported threads/dynamic-loader/native boundaries, bounded array/collection/string previews, unknown provenance when not recorded, and process-pipe order not provable relative to recorder facts. Phase 5.5 should prioritize novice usability, very short split layouts, arbitrary long names/values, sparse/ragged-array navigation and sustained dense-world GPU/text-memory profiling. Phase 6 is not started.
