# Phase 2 — incremental trace pipeline and scalable history

Base `14e2a17`, branch `kiro-runtime-audit`. Phase 2 changes processing and transport only. Java coverage, constructor semantics, Spatial placement, design tokens, process/observer separation, watchdogs and recorder budgets remain unchanged.

## Recorder → retained raw archive → browser

`CaptureReader` accepts contiguous NDJSON v1 facts into a private append-only file. It retains counters and a sparse byte index every 256 records, rather than an array of all decoded raw objects. A failed append leaves the last committed prefix addressable and stops observation with STOPPED_ERROR; it does not stop or relaunch Java. Failure to initialize the archive is classified as observer preparation before any application child is created, with prepared files cleaned up; Run can use its existing plain fallback exactly once. Debug reports that preparation failure without launching a child. The archive remains readable after the preparation directory and writer close. At most 32 recorder sessions retain archives. Eviction and graceful disposal close/remove them. Cleanup failure cannot propagate into another JVM launch. Abrupt termination can leave temporary files.

Normal live execution requests select `transport=delta`. Metadata has transportVersion 1, rawEventCount, recording/process/build/source/Console fields and `rawEvents: []`. SSE `raw` messages use protocol v1 with sessionId and zero-based, end-exclusive raw sequence ranges. Raw sequence is independent of normalized semantic cursor. The normal path sends only the new range, normally once. Reconnection deliberately can retransmit a bounded range.

The default page is **256 records**, capped at **1024 records** and a **256 KiB byte target**. One indivisible recorder record may exceed the byte target, up to the unchanged recorder byte budget. Each SSE tick sends at most four pages every 100 ms. A subscriber retains one cursor and the latest metadata, never its own history queue. Node `write(false)` has accepted the frame: publication pauses until `drain` instead of immediately reconnecting and repeatedly resending large metadata. A one-second stalled-drain deadline disconnects an actually slow response, with a one-second destruction fallback. An oversized frame is rejected before writing. The 40 MiB response ceiling accommodates the existing 32 MiB inline Console metadata. No transport pressure reaches the JVM or changes semantic recorder budgets.

`GET /api/execution/:id/raw?from=N&limit=L` supplies an accepted contiguous range. The client reconnects with its **committed**, rather than merely delivered, sequence. Gaps are rejected before the later batch is applied and repaired from this endpoint; an unavailable gap is an error, not an apparently complete history. Duplicate and overlap delivery checks raw positions and compact length/two-hash evidence, applying only the new suffix. Fingerprints detect ordinary accidental conflicting retransmissions; they are not cryptographic authentication of an untrusted server. Sessions and protocol versions must match.

The client holds at most 2 MiB of ordinary pending UTF-16 raw-message data. One indivisible frame can use up to 17 MiB when the queue is empty, so a valid large record cannot cause an endless reconnect loop. Overflow closes delivery, drains accepted work and resumes. Metadata/Console is handled separately from this raw-processing queue. Metadata can arrive ahead of raw data: the normalizer finalizes completion or CAPTURE_STOP only after consuming the advertised raw head. STOPPED_LIMIT/UNSUPPORTED/ERROR therefore never fabricate a Java end or later values.

The client also accepts explicitly supplied old inline snapshots without transportVersion, applying only their new suffix through the same ingest/history and checking duplicate evidence. Only this compatibility path checks old inline facts. Explicit legacy snapshot APIs remain available, as does SSE `transport=legacy`. They intentionally materialize a full raw array only when requested. Raw v1 and semantic schema v1/v2 archives remain readable; no migration or format reinterpretation is needed. These local temporary raw files are session retention, not durable project archives.

## One semantic head below React

`TraceNormalizer` retains raw-normalization indexes and one `ExecutionHistory`. Every newly emitted semantic event is frozen, validated and reduced once. The normalizer, ingest layer and UI seek all share that history. There is no second normalized-state engine or replay from zero for a live publication. React receives a separate stable presentation trace with persistent event-array roots: only new event references are appended at publication. Between publications its exposed length does not change, even when Console metadata triggers a parent render. That prefix is bound to the same validated history; seeks remain bounded by its published cursor and never dispose/reduce the live head. Validating a prefix checks its own terminal state, not the later full head. This closes a convergence finding where the growing normalizer array leaked unthrottled changes into React despite a publication timer. Batch `normalizeTrace` remains a compatibility wrapper; independently verified Phase 1 golden hashes preserve exact event/diagnostic/capability output.

`IncrementalTraceValidator` maintains event IDs, source line counts and scope opt-in watermarks. A newly introduced explicit scope can reject a previously incompatible eager declaration without rescanning events. Semantic transitions still reside in `applyEventWithStorage`; the two-argument pure `applyEvent` uses plain copies as the reference oracle. The efficient engine supplies persistent collection operations and auxiliary lookup indexes. Both execute the same validation and semantic transition cases.

Record maps and arrays expose their established consumer interfaces through immutable proxies over 32-way persistent radix structures. Array targets stay empty and virtualize length, avoiding proportional backing-hole allocation on every append. Record enumeration preserves JavaScript integer-key ordering and null values. Writes copy changed paths, not all frames/objects/returns. New values are frozen. Auxiliary scope, loop, lifetime, display-ID, input and exception indexes share the snapshot lifetime and derive from runtime facts. Starting from a checkpoint reuses these roots. Failure never publishes an invalid head. Proxies are internal and not structured-cloneable; JSON remains the wire/export boundary. Tests that need mutable forged snapshots explicitly deserialize JSON.

## Checkpoints, cursor and lifetime

History uses an append-only event-reference array (amortized append), a current immutable head, periodic shared checkpoint roots and one recent historical materialization. Default initial spacing is **256 semantic events**. The total retained root budget is **256**, including origin, live and the recent cursor. When the periodic allowance fills, every other checkpoint is retained and spacing doubles. Lookup is binary search plus suffix replay. Sequential stepping reuses the recent state. Return to Live retrieves the already computed head.

The root bound is not an absolute memory bound on semantic truth: event and entity storage must grow with accepted facts. Production recording still stops at 20,000 raw records/8 MiB/256 identities/128 live frames. Synthetic probes deliberately test larger histories without increasing those production limits. The policy benchmark measures 16/64/128/256 roots; 256 gives better distant-scrub latency for modest additional retained memory. See PERFORMANCE.md for empirical overhead and limits.

A historical cursor is independent from the live head. App recomputes append-derived layout/transitions using event count while a fixed historical seek can reuse its unchanged state. LIVE follows current recorded truth; HISTORY is not advanced by an arriving batch. Console uses actual process metadata independently. UI ingestion advances 32-record slices and yields through MessageChannel after about 4 ms; live visual publication coalesces to the existing 100 ms cadence. When metadata advertises a raw backlog, intermediate world projections are deferred until the latest advertised head is consumed, then published once. A faster producer may therefore skip transient visual frames while every accepted fact stays in history; slow/interactive producers continue to publish at the existing cadence. This prevents expensive transient dense worlds from starving catch-up; process/Console metadata still updates immediately. Before the first raw fact arrives, the ready placeholder remains visible. A single unusually expensive event/GC can exceed the slice target. This is cooperative scheduling, not a hard realtime guarantee or a Worker claim.

WeakMap caches follow trace ownership. A project/session switch disposes the old ingest and pending presentation timer. Events in attached traces are immutable; explicit validation of legacy mutable traces rebuilds their history. Prefix boundary replacement or truncation also resets legacy caches. The generic layout builder adds only new anchors/ports/bounds, preserving the old batch layout as an oracle. Curated scoped composition remains unchanged. Motion transitions reuse adjacent states from shared history, keyed by trace identity rather than demo name.

## Deliberately deferred

Dense-world scene-model/detail generation and WebGL draw/label/camera costs are still presentation work over the visible world. This phase does not redesign their placement or LOD. Console metadata still resends its bounded inline strings, and explicit legacy/full archive serialization remains linear. Million-event scrub tails and retained memory are documented; no claim of a rendered million-entity scene is made. Constructor semantics, generalized types/collections, concurrency worlds, IDE shell and Phase 3 remain deferred.
